 # Day 5: Resume Parser and Job Matcher

This project uses a Groq large language model (LLM) to read a job description, extract its important requirements, parse resumes, and rank candidates by how well they match the job.

The program supports resumes in these formats:

- PDF (`.pdf`)
- Microsoft Word document (`.docx`)

## What This Project Does

The complete flow is:

```text
Job description
	|
	v
LLM extracts structured job requirements
	|
	v
Read every PDF/DOCX file in resumes/
	|
	v
LLM extracts structured resume information
	|
	v
Compare each resume with the job description
	|
	v
Calculate a match score and collect details
	|
	v
Sort candidates and print the top 2 and lowest 2
```

## Important Concepts

### 1. LLM

An LLM reads unstructured text and returns useful information. In this project it reads both the job description and resumes.

### 2. Structured output

The LLM response is requested as JSON. Pydantic models then validate that JSON and make the data easier to use in Python.

### 3. Resume matching

The final score is generated by comparing the extracted job requirements with the extracted resume details. It is an AI estimate, not a guaranteed hiring decision.

## What Happens During Execution

### Step 1: Load configuration

The script loads `GROQ_API_KEY` from `.env` and creates a Groq client. If the key is missing, the program stops with an API-key error.

### Step 2: Parse the job description

The job description is written in `resume_parser.py`. The first LLM request extracts:

- Role
- Required skills
- Preferred skills
- Minimum experience
- Education requirements
- Responsibilities

The result is validated using the `JObD` Pydantic model.

### Step 3: Read each resume

The script loops through the `resumes/` folder:

- PDFs are read with `pypdf`.
- DOCX files are read with `python-docx`.
- Other files(like screenshots) are skipped.

### Step 4: Parse the resume

The second LLM request converts resume text into a `Resume` object containing fields such as name, contact information, skills, experience, education, projects, and certifications.

### Step 5: Compare the candidate with the job

The `final_score()` function sends the structured job and resume data to the LLM. The response contains:

- A score from 0 to 100
- Matching and missing information in `details`
- Whether the experience requirement is met
- A short verdict

The response is validated with the `MatchResult` model.

### Step 6: Rank candidates

All candidates are sorted by score in descending order. The program prints:

- `TOP 2 CANDIDATES`
- `LOWEST 2 CANDIDATES`

## Dummy Example Flow

This is a small fictional example to show what happens inside the program. It does not require creating these files or making an API request.

### Input 1: Job description

Imagine that the job description says:

```text
Role: Python Developer
Required skills: Python, SQL, REST APIs
Preferred skills: Docker, AWS
Minimum experience: 1 year
Education: Bachelor's degree in Computer Science
```

### Output 1: Structured job data

The LLM converts the text into data similar to this:

```json
{
	"role": "Python Developer",
	"required_skills": ["Python", "SQL", "REST APIs"],
	"prefered_skills": ["Docker", "AWS"],
	"minimum_experience": 1.0,
	"education_requirements": ["Bachelor's degree in Computer Science"],
	"responsibilities": ["Build and maintain Python services"]
}
```

The `JObD` Pydantic model checks that the response has the expected fields and data types.

### Input 2: Candidate resume

Suppose `resumes/alex-example.docx` contains:

```text
Name: Alex Example
Education: Bachelor's degree in Computer Science
Experience: Python Developer, 2 years
Skills: Python, SQL, REST APIs, Docker
Projects: Built a book-search REST API
```

### Output 2: Structured resume data

The `parse_resume()` function sends the resume text to the LLM and receives data similar to this:

```json
{
	"name": "Alex Example",
	"email": null,
	"phone": null,
	"total_experience_years": 2.0,
	"skills": ["Python", "SQL", "REST APIs", "Docker"],
	"experiences": [
		{
			"company": null,
			"role": "Python Developer",
			"duration": "2 years",
			"description": null,
			"skills_used": ["Python", "SQL", "REST APIs"]
		}
	],
	"education": ["Bachelor's degree in Computer Science"],
	"projects": ["Built a book-search REST API"],
	"certifications": []
}
```

The `Resume` Pydantic model validates this response.

### Comparison result

`final_score()` compares the two structured objects. A fictional response might look like this:

```json
{
	"score": 90.0,
	"details": {
		"candidate_name": "Alex Example",
		"matching_skills": ["Python", "SQL", "REST APIs", "Docker"],
		"missing_important_skills": ["AWS"],
		"experience_requirement_met": true,
		"verdict": "Strong match for the Python Developer role."
	}
}
```

The program then adds Alex to `all_results`, sorts the list by `score`, and prints Alex in the ranking if the score is high enough.

## Common Problems

### `API key is missing!!`

Check that `.env` exists in the same directory where the script is run and contains `GROQ_API_KEY`.

### `ModuleNotFoundError: No module named 'pypdf'`

Install the document packages:

```powershell
uv pip install pypdf python-docx
```

### No resumes are processed

Check that the files are inside `day5/resumes/` and use `.pdf` or `.docx` extensions.

### PDF text is empty or incomplete

Scanned PDFs may contain images instead of selectable text. This script does not perform OCR, so such files may need to be converted to text first.

### Requests are slow or rate-limited

Each resume requires two LLM requests. The script waits five seconds between requests to reduce the chance of rate limiting. More resumes therefore take longer and may increase API usage.

## Code Structure

The main functions have these responsibilities:

| Function | Responsibility |
| --- | --- |
| `read_pdf()` | Extract text from PDF pages |
| `read_docx()` | Extract text from Word paragraphs and tables |
| `read_resume()` | Select the correct reader based on file extension |
| `parse_resume()` | Convert resume text into a validated `Resume` object |
| `final_score()` | Compare a resume with the job and return a validated score |

## Safety and Privacy

Resumes may contain personal information such as names, email addresses, phone numbers, and employment history. Review the privacy requirements for your environment before sending resumes to an external API. Keep API keys and private resumes out of source control.

## Possible Improvements

- Move the job description into a separate text file.
- Add `pypdf` and `python-docx` to `pyproject.toml` so setup is automatic.
- Save results as JSON or CSV instead of printing them only.
- Add error handling for unreadable files and failed API requests.
- Add OCR support for scanned PDFs.
- Avoid mutable list defaults in Pydantic models by using `Field(default_factory=list)`.
